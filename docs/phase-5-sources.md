# Knowledge source API and database foundation

Source management defaults off (`SCHEDULER_KNOWLEDGE_ENABLED=false`). Enabling it permits a manager to save text, FAQ, HTTPS URL and raw PDF/DOCX/TXT/MD files under an agent. It does not enable embeddings or processing. Capabilities truthfully report `processing_available=false` with `processing_unavailable` when source management is enabled. Newly saved sources remain queued until an ingestion worker is introduced and qualified. No models, parser dependencies or embedding credentials are needed to start the API.

The API lives under `/dashboard/agents/{agent_id}/knowledge`. Managers can list/create sources, read/update/delete a source, reindex with its current revision, and read a bounded preview of an active generation. A protected source detail returns `SourceDetailOut.input`, discriminated by `kind`: text/format, FAQ question/answer, URL, or file format only. Name/revision remain on the outer response; lists and mutation receipts remain metadata-only. This explicit input projection supports editing before processing is available and never exposes internal JSON, raw files or blob capabilities. Every mutation requires an `Idempotency-Key`. Updates/reindex carry `revision` in JSON; deletion carries it in the query. Replaying the same key and normalized body returns its saved response before checking the old revision, including a delete retry. A different body or operation under that key conflicts. Source kind and ownership are immutable. Reindex/replacement retains the previous active generation while new work is queued; deletion immediately removes availability and cancels outstanding leases.

Files use raw `application/octet-stream` bodies, `name`/`format` query parameters and an `X-Content-SHA256` header. Creation uses `POST /sources/upload`; replacement uses `PUT /sources/{id}/content?revision=...`. Authentication, agent ownership and replay checks run before stream consumption. No row locks span streaming; revision and manager authority are checked again at commit. Synchronous database work runs outside the asynchronous upload event loop so concurrent retries can complete their transactions. Receipts, sources and jobs commit together.

Files are limited to 10MiB of actual stream bytes and a 30-second stream/admission deadline. Private storage reserves 4GiB free disk and caps physical use at 1GiB; at most 64 undeleted sources belong to an agent. Files use server-generated tenant/source/revision identifiers with private directory/file permissions. The store rejects symlinks, verifies the complete digest and cleans partial files on error/disconnection. Complete files whose database outcome is uncertain remain private; the later cleanup worker must remove only server-owned unreferenced keys older than 24 hours. No public response exposes a blob path or a download capability. File parsing/magic verification and public-URL DNS/redirect protection belong to the ingestion worker; queued upload acceptance does not assert successful parsing or readiness.

Compose keeps project `voice-agent-phase1`, ports 55432/55433 and the existing `postgres-dev-data` volume. Both databases use the pinned PG16/Bookworm pgvector image in `compose.yaml`. Back up the development database and role credentials privately before replacing its image; never reset its data or volumes. Migration 0007 adds the vector extension, forced-RLS source/generation/chunk/job/query-event tables, composite ownership constraints and worker-only discovery. `knowledge_worker` starts NOLOGIN; `scripts.init_db.init_database` accepts an optional distinct worker password while preserving the original two-argument API and existing credentials. The worker cannot read patients, appointments, users, versions or session data. Cross-tenant job discovery returns routing identifiers only. The API role cannot execute discovery or generation activation. Tenant-context claim and final lease checks lock Source before Job, enforce revision/token/expiry and cap attempts at three; an expired final attempt becomes failed. `knowledge.queue.activate_generation` calls a narrow database function that validates tenant/source/revision/profile and the processing lease against database wall time after locks. It accepts only complete nonempty contiguous chunk sets, then atomically seals the generation and activates it. Sealed generations reject later chunk insertion permanently, including after replacement. This is an authority boundary for the later ingestion worker; no ingestion process is started here. Query outcomes include nullable `redacted_question` limited to 1000 characters; the later query layer must decide when retaining a redacted question is safe.

The API's private storage is the `knowledge-private-data` named volume at `/var/lib/knowledge`, owned by the nonroot API user. Native development defaults to `.local/knowledge-blobs`. The optional embedding composition uses the same project name and a `knowledge` profile; its secret interpolation is optional so loading the overlay with the profile disabled does not block ordinary API/source management. Explicit embedding startup still requires its own valid secret and remains disabled without `EMBEDDING_ENABLED=true`.

The official [pgvector Python adapter 0.5.1](https://pypi.org/project/pgvector/0.5.1/) is MIT licensed, supports Python >=3.10 and supplies a universal Python wheel. Its installed metadata declares no mandatory dependencies; the API does not acquire numpy, ONNX Runtime, tokenizers or parser packages through this adapter. The [pgvector extension](https://github.com/pgvector/pgvector) uses the PostgreSQL License. Retain their license notices when distributing an image. Exact artifact hashes are locked in `uv.lock` and Compose. This checkpoint adds schema and API controls; actual parsing, worker-driven ingestion, cleanup, retrieval and model quality remain later acceptance work.

Verification uses only `voice_agent_test` and synthetic files. Run one database suite at a time: `uv run --locked pytest`, Ruff lint/format, mypy, and all three public contract exporter `--check` commands. `tests_knowledge/test_sources.py` covers mounted raw routes, receipt/revision retries, concurrent unknown outcomes, RLS/roles/composite ownership, quota/deadline/digest cleanup and lease fencing. Its inserted generation metadata is an explicitly synthetic test fixture, not evidence of real inference.
