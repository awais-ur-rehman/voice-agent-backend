## Approach

Use a durable, tenant-scoped analytics event ledger with normalized call/session records, per-turn measurements and idempotent hourly/daily rollups. A separate bounded worker builds summaries, aggregates, alert state and retention cleanup from that ledger. The dashboard consumes typed read projections. This is preferable to reading expiring recovery checkpoints at page load (incomplete and privacy-sensitive) or adding a third-party analytics service (unnecessary network/credentials and PHI exposure).

Reuse existing Python/Postgres/Valkey, API auth, RLS, React/TypeScript/TanStack Query, shared dashboard/table/dialog/form primitives and fonts. No chart dependency is required: accessible simple SVG/bar visualizations plus text tables are sufficient. OpenTelemetry API is already locked transitively; promote its exact pinned version only after primary-source license/compatibility verification if directly importing it. No provider SDK/model substitution or heavy inference.

## Privacy, transcripts and retention

Raw audio remains unrecorded (optional spec feature; do not implement recording). Transcript capture defaults OFF per tenant and is editable only by owner/admin. When off, neither caller text nor assistant prose is retained in analytics. Review still shows safe event/tool/metric metadata with “Transcript capture was off.” Existing transcript-free recovery behavior remains unchanged.

When explicitly enabled, record bounded caller/assistant text in a separate RLS-protected transcript table, not log/telemetry attributes. Redact exact known patient/contact literals from state and current command arguments plus phone/date/email patterns for English/Urdu digits; do not claim arbitrary bilingual name recognition or perfect de-identification. UI consent/configuration copy explains sensitive content can remain; admins must arrange caller notice/consent. Capture setting is snapshotted per session and cannot retroactively capture an existing session. Do not log request bodies. Manager-only transcript detail, settings and transcript deletion; staff can view safe metadata, not transcript text. Deletion-on-request deletes text immediately and remains deleted after retries/worker refresh.

Transcript retention default7days, allowed1–30days; safe event/metric/call retention90days and rollups365days. Shortening retention makes older transcript text inaccessible immediately, then bounded worker cleanup removes it. UI shows expiry/off/deleted reasons without inventing a transcript. Worker may purge analytics-only records; never patient, appointment, auth, source/blob or recovery records. No browser persistence of transcript, query or patient data. Knowledge gaps use keyed fingerprints/outcomes without raw questions, preserving Phase5 NULL-question policy.

## Measurements and definitions

All stage durations are finite, nonnegative and bounded (max600000ms). Text command_total/tool/LLM completion durations are not relabeled speech latency or LLM first-token latency. Measure STT completion from actual adapter elapsed time, TTS first byte only if actually observed, and end-of-speech to first published audio with actual native timestamps. Missing first-token/byte measurements remain null with sample counts. Native event ingestion must require current worker generation/lease+runtime authority, bounded batch/body and idempotent IDs; browsers cannot submit trusted metrics. Expired/stale/ended workers cannot alter a call.

Provider usage uses actual reported token counts, never estimates from text length. Snapshot model and configured price rates if available; absent usage/rates means cost=null with coverage counts, not zero. Clinic owner/admin sees own clinic usage, no cross-tenant platform dashboard or credentials. If the platform-owner cost view cannot be safely represented by existing roles, explicitly retain it as an operator report rather than inventing a superuser HTTP role. No new hosted calls are necessary for tests/demo.

Overview: voice call count and separately text/session count; created/rescheduled/cancelled operations; conversion=ended sessions with a successful booking/eligible ended sessions in the selected channel; average ended duration; handoff and abandonment rates with explicit denominators. Quality: attempted/completed tasks from executed state transitions (not initial default task=book), tool failure/result counts, repeated code-owned prompt-without-progress rate and average turns per attempted task. Info-only/unknown/active/error sessions and zero denominators stay explicit/null. Count unanswered queries and failure/unavailable reasons separately; do not equate paused embeddings with irrelevant knowledge.

Session outcome is last successful appointment operation unless later terminal error/handoff determines the terminal outcome; operation counters remain independent. Preserve actual end reasons. Expired nonterminal sessions finalize as abandoned using authoritative expiry, not page-access time. Duration uses real start/end timestamps, not an active timeout as a completed call. A bounded async worker produces deterministic fact-only summaries from canonical events, never a new LLM call or clinical narrative.

Filters: tenant-owned agent, channel(all/text/voice), inclusive start-local-date range <=31days, outcome, review flags and pagination(max100). Capture each session's timezone at start; date/hour buckets retain that historic timezone. Explain this in filter help and show explicit timezone in detail. DST and timezone changes cannot silently relabel historical sessions. Daily/hourly bucket keys include tenant/agent/channel/purpose/local date/timezone; worker recomputes affected buckets rather than incrementing counters, so retries/late metrics/retention are consistent. Quantiles use underlying metric samples or exact mergeable samples within the bounded range; never average p95 values. Return freshness/as_of and counts/coverage. One consistent database snapshot per projection prevents mismatched totals/tables.

### Consent safety and live-setting ordering

Existing emergency detection, explicit handoff and end-session control precede pending recording consent. They run locally with capture disabled; never hold an emergency behind a recording question or call a planner for consent. Cover an emergency as the first utterance with capture enabled/pending. For a bilingual agent, the code-owned consent notice must be understandable in both supported languages; input matching follows exact normalized whole phrases, not substring yes/no. No opt-in can substitute for appointment/patient confirmation.

Serialize transcript insertion against settings disable/retention changes using a shared current-settings row lock held through the insert transaction (manager settings update takes the conflicting lock). Manager settings mutation must not lock active call/session rows after settings; transcript deletion locks only its call/tombstone in the same order as insertion. Refresh settings state rather than trusting an ORM cached value. An insert committed before disable is visible under policy; none can commit after disable using a stale enabled value. Default-off callbacks stay privacy-safe. Worker purge/settings reads never acquire locks in a reverse lifecycle order. Prove concurrent disable-vs-insert and delete-vs-insert with controlled two-connection tests.
