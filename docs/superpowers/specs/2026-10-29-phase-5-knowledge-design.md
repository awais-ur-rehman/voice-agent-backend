## Intent and scope

A clinic manager can upload PDF/DOCX/TXT/MD, paste text, add a question/answer FAQ or public HTTPS URL, inspect processing, re-index and delete a source. An agent answers English/Urdu questions from its own ready clinic knowledge, offers a callback when information is absent or unavailable, and resumes scheduling without gaining any new scheduling authority. Knowledge changes become available after processing without republishing the agent (v0.1 section3.8). Ready means indexed, not medically or factually certified content.

Do not execute further real-model inference at this checkpoint. Artifact verification, control-boundary tests and separately labelled hosted answer-adapter probes may proceed. Actual CPU vectors, bilingual/cross-language quality, live ready ingestion and end-to-end grounded retrieval remain pending.

## Approaches and technical choice

1. Original full-precision BGE-M3 locally: original ONNX external weights are about2.27GB before runtime overhead; a poor initial fit for this8GiB machine's constrained headroom.
2. Hosted embedding service: introduces another service/data path; NVIDIA currently labels BGE-M3 deprecated. Do not assume its hosted endpoint works or silently substitute another embedding model.
3. Selected: pinned INT8 ONNX export of BGE-M3, local CPU service, with an actual bounded preflight/quality evaluation. This retains the specified model/dimensions and keeps ingestion/embeddings local. Quantization is not treated as quality acceptance; if the preflight fails, keep readiness false and report the concrete resource failure rather than raising caps or claiming model-backed acceptance.

Primary research: [BAAI model](https://huggingface.co/BAAI/bge-m3), [HF Staff ONNX export](https://huggingface.co/Xenova/bge-m3), [artifact tree](https://huggingface.co/Xenova/bge-m3/tree/main/onnx), [NVIDIA status](https://build.nvidia.com/baai/bge-m3), [pgvector](https://github.com/pgvector/pgvector). FastEmbed's BGE-M3 support PR602 is still open and the current supported-model registry omits it; do not force that unreleased integration.

## Local services and model profile

API, ingestion worker and embedding service are separate processes. The API never imports ONNX/model weights. The embedding service has no database or raw-document credentials/mounts; only the pinned model cache. Ingestion gets a narrow nonowner/NOBYPASSRLS role and the private blob store, not patient/appointment/auth-table access. Internal embedding RPC uses a distinct generated server secret, strict bodies and a private Compose network; any host port binds127.0.0.1. Nothing exposes this capability to the browser/public schema. API processing capability will derive from fresh authenticated private worker status and actual embedding/artifact readiness observations; configuration flags or credentials alone never constitute readiness. Processing and ready-corpus query availability differ. Health checks never trigger tokenizer/model loading or inference; real model qualification remains separately pending.

Profile: base `BAAI/bge-m3`; artifact repo `Xenova/bge-m3`, revision `4de13258303883538bd53b696b452bf8099f0858`; `onnx/model_int8.onnx`,568456694 bytes, SHA256 `a206e10e995aa2a833924bcd725ba5dd6c3425cd34bac3cf2b5677cd2a1c51d6`; `tokenizer.json`,17082821 bytes, SHA256 `6710678b12670bc442b99edc952c4d996ae309a7020c1fa0096dd245c2faf790`. ## Source API and ingestion

Manager-only per-agent routes: list/get; create pasted text or FAQ or URL; raw authenticated file upload; re-index; delete; extraction preview and retrieval test. List/mutation outputs remain metadata-only. Protected source detail adds an explicitly typed current-input view for text, FAQ and URL editing even while processing is unavailable; files expose only format metadata. No arbitrary internal JSON, raw file bytes, blob path/key or download capability is returned. All writes capture identity/revision and use receipt-bearing idempotency. Fresh revisions/conflicts must be explicit; no newer operation may replace an unknown intent.

Use a raw binary upload route with format/name metadata and digest header so auth completes before Request.stream consumes file bytes; avoid unauthenticated multipart spooling. Enforce actual stream bytes and a30s upload deadline, not just Content-Length. JSON sources have bounded fields; raw file type is verified by parser/magic, not extension alone. The typed client must support Blob bodies and retained File/digest/key retries without JSON stringification/storage. Persist and enqueue only verified complete blobs; clean interrupted temporary files. Raw-file checksum is verified; retries cannot create duplicate sources/jobs.

Worker pipeline: queued→processing→ready or failed with safe code/message. Parse PDF/DOCX in a bounded subprocess (512MiB/20s); reject encrypted/scanned/no-text inputs clearly. DOCX is read without extracting arbitrary archive paths or external relationships. TXT/MD decode strict UTF8; preserve headings and preview extracted text. The worker entrypoint loads the verified pinned tokenizer only after readiness and passes it explicitly to processing; disabled/unavailable startup never loads it. Chunk with the pinned tokenizer,300–500 tokens and50-token overlap, respecting English/Urdu sentence boundaries and hard-splitting oversized sentences. Preserve source/section/ordinal metadata; never silently truncate a document to mark it ready.

URL ingestion is single-document, public HTTPS only, no credentials or secret query parameters. Resolve/check every redirect (max3), reject any private/loopback/link-local/reserved destination, pin the validated IP while verifying TLS/SNI/Host for the original hostname, cap bytes/time/decompression, and never fetch linked assets. Tests cover DNS rebinding/redirect/mixed-IP cases; no real private-network probe. This supports public links, not localhost or authenticated portals; files/paste cover local material.

## Retrieval and grounded replies

Per agent/tenant, latest ready active generations only. Query embedding outside SQL locks; top20 vector and20 keyword candidates, reciprocal-rank fusion k60, top4 chunks. Relevance gate uses actual cosine (initial0.55), not RRF rank score; evaluate English/Urdu/cross-lingual positives and unrelated negatives before changing it. RLS/agent filters must not starve authorized recall behind a large foreign-tenant corpus; rank only the bounded MATERIALIZED authorized active corpus with exact cosine, and test foreign-tenant/agent dominance plus an upper-limit plan/timing observation. This path does not rely on global approximate filtering/fallback. Profile mismatch requires re-index, never comparing incompatible vectors.

Public preview returns bounded excerpts, source IDs/headings/lang/scores and reason. Distinguish no_sources/below_threshold from embedding/answer unavailable. Technical unavailability must not be presented as proof the KB lacks information.

Keep planner action arguments empty for backward compatibility; effective search query comes from current caller text, not a model rewrite. Prepare retrieval and a separate bounded grounded-answer operation outside the SQL command transaction. The action planner remains JSON-actions-only. The answer adapter uses the same Nemotron request budget/thinkingfalse and a15s knowledge deadline; it has no scheduling tools. Require structured answer/source IDs/exact evidence quotes; reject foreign/stale IDs, nonliteral evidence, extra fields, empty/unbounded prose and no-answer responses. Do not let document/caller instructions change policy or execute actions. Structured prices/hours/profile route ahead of document answers and win conflict tests; cross-language replies retain the caller language. Model grounding is evaluated rather than claimed as a formal semantic guarantee.

Before committing a reply, recheck runtime/parent authority, command/revision and active source generations; take short shared source locks in sorted order to serialize with delete/re-index. Do not hold source/session SQL locks across network inference. A stale prepared answer is discarded safely. Log one privacy-preserving query outcome per command (keyed fingerprints,language,purpose,decision,refs/scores,duration); keep nullable redacted_question NULL at this checkpoint rather than relying on incomplete arbitrary bilingual-name detection. This supports grouped outcomes, while representative question text needs a separately reviewed safe policy. Never retain raw patient factors/transcripts/provider bodies in these logs. Keep knowledge text out of retained conversation history. Source content is reference data, never privileged prompt instructions.

FAQ routing is code-owned while identity collection is pending. Bare phone/date/name factors continue through the existing local identity path. A clear public question (English/Urdu interrogative prefix) with no identity, booking or subject-change fragment may use knowledge. A question mixed with a phone/date, identity-labelled fragment, known candidate identity literal, or competing booking/family change is ambiguous: return a bilingual request to give the identity detail and clinic question separately; do not call a hosted model, increment attempts, verify/create a patient or change the subject. Unclassified question-shaped input is also clarified locally. An unmatched bare factor still uses the existing failed-verification limit; this is not an unlimited-guess bypass. Emergency handling stays first. Examples to pin: bare `1990-01-01` remains local verification; `What documents should I bring?` can use KB without changing attempts; `My date of birth is 1990-01-01; what should I bring?` is local clarification with zero hosted calls and no identity mutation. Known candidate names/DOB are used only ephemerally for redaction/classification, never prompt/log content. This conservative ambiguity rule is the controller's builder-check resolution; its cost is an extra clarification for mixed utterances.

FAQ digressions during patient lookup/verification must not consume an identity attempt or create a patient. Literal identity factors remain code-consumed and withheld from external requests. Preserve task/hold fields across a knowledge answer. Invalidate a prior booking/patient confirmation binding after a digression and require a fresh code-owned readback before any later yes can commit; never treat acknowledgment of the FAQ as booking consent.
