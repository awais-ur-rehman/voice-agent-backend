# Private CPU embedding service

The API imports only `knowledge.profile` and `knowledge.embedding`. `EmbeddingClient.embed(texts, deadline=...)` takes an absolute `time.monotonic()` deadline and exactly one nonempty text. All unavailable/invalid responses raise `EmbeddingUnavailable` with a fixed safe reason. The synchronous client bounds caller latency with a deadline and at most five background RPC slots; a timed-out transport can retain its slot until its bounded socket operation exits. Response streaming is size-limited and checks the deadline between chunks. Caller code must perform inference outside database transactions. Profile fingerprint covers the complete pinned file manifest, CLS pooling, L2 normalization, no prefix, dimensions and the reject-over-512 policy. It must be stored with every index generation.

`knowledge/profile.json` pins the Xenova BGE-M3 export at `4de13258303883538bd53b696b452bf8099f0858`. All six files are checked for exact size and SHA256 on each child load. Unknown files and symlinks are rejected. The pinned model card declares MIT; the base BAAI model card also declares MIT. Neither model repository has a standalone LICENSE file at the revisions checked. Required runtime files are ONNX and tokenizer JSON; config, special-token metadata, tokenizer configuration and the model card are retained and hashed as provenance. No remote Python or pickle is used.

Package metadata was rechecked on 2026-10-29 before installation: onnxruntime 1.31.1 (MIT), tokenizers 0.23.3 (Apache-2.0 classifier), numpy 2.5.4 (BSD-3-Clause plus bundled 0BSD/MIT/Zlib/CC0 notices), psutil 7.2.2 (BSD-3-Clause). Python 3.12 wheels exist for macOS arm64 and Linux arm64/x86_64. ONNX Runtime requires numpy, flatbuffers, packaging and protobuf; tokenizers requires huggingface-hub. Exact transitive versions and wheel hashes are in `uv.lock`; retain installed wheel LICENSE/NOTICE files when distributing images. Source-only adoption does not replace redistribution review. psutil is also a development dependency for supervisor tests; runtime API installs neither development nor embedding groups.

Real model acceptance is pending by owner choice. Normal service startup defaults `EMBEDDING_ENABLED=false`: health and API/worker startup cannot load the real model even if RAM improves. The private route returns unavailable until explicit owner-authorized opt-in (`EMBEDDING_ENABLED=true`). Artifact verification alone never sets ready. The explicit smoke command below also loads the model and must remain deferred until that acceptance work is authorized.

Explicit local preparation:

```sh
UV_CACHE_DIR=.local/uv-cache uv sync --locked --group embedding
UV_CACHE_DIR=.local/uv-cache uv run --locked --group embedding python -m scripts.prepare_knowledge_assets bootstrap
UV_CACHE_DIR=.local/uv-cache uv run --locked --group embedding python -m scripts.prepare_knowledge_assets verify
UV_CACHE_DIR=.local/uv-cache uv run --locked --group embedding python -m scripts.prepare_knowledge_assets smoke
```

Bootstrap stages only allowlisted immutable URLs, bounds bytes and preserves a 4GiB disk reserve. An absolute 300-second budget covers all download workers, including process startup, DNS/open/redirect and blocked reads. Expiry or cancellation kills and reaps the isolated worker before the temporary staging directory is removed. A failed download is removed, never adopted. No HTTP route downloads artifacts. Smoke emits fingerprint, dimensions/norm, timings and RSS, never input text or vector values. A memory/resource failure is not model acceptance or bilingual quality evidence.

Generate a fresh private bearer into ignored `.local/embedding.env` with mode 0600. It must contain only `EMBEDDING_SECRET=<at least 32 random characters>`; never pass `.env` or `.env.api` to this service. Start with `docker compose --env-file .local/embedding.env -f compose.embedding.yaml up -d --build`. This separate composition has a private internal network, localhost-only port 8001, readonly model mount, no raw-document/database mounts, two CPU quota, 2GiB container ceiling and nonroot user. It does not recreate existing API or database services. Attach future API/ingestion callers explicitly to the private network; no browser route exposes this RPC.

The child uses CPUExecutionProvider, two intra-op/one inter-op threads, one active request and four waiting slots. HTTP admission reserves one of five slots after authentication and before reading a body or submitting to a dedicated executor; cancellation retains a submitted operation's slot until that operation actually completes. Tokens include special tokens; longer inputs are rejected rather than silently truncated. Watchdog polls RSS/deadline every 25ms; cap 1536MiB, admission floor 1792MiB available (host and Linux cgroup v2 minimum), startup 120s, inference/request 10s. Threshold enforcement is sampled and can overshoot between samples; the container limit is a second ceiling. Parent disappearance is watched independently in the child. A killed child fails readiness; restarting the service or explicitly calling `Supervisor.start()` revalidates resource floor and every artifact. Requests do not restart an unhealthy model. Public health responses expose booleans only.

The API and embedding Docker targets are separate. No voice execution, GPU fallback, reranker, database schema or knowledge ingestion behavior is enabled here. Model-backed cross-lingual quality remains a later acceptance gate.
