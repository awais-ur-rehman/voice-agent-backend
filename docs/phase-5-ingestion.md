# Private knowledge ingestion

The knowledge worker is a separate, opt-in process. Real model acceptance remains pending: `KNOWLEDGE_WORKER_ENABLED=false` and `EMBEDDING_ENABLED=false` are the defaults. A disabled worker does not connect to the database, inspect model/tokenizer assets or perform inference. When enabled, it checks actual embedding-service readiness before loading its verified tokenizer or claiming a job. Intentional unavailability leaves jobs queued without consuming attempts. The API capability still reports processing unavailable at this deferred checkpoint.

`process_job(factory, blob_store, embeddings, lease, *, clock, tokenizer)` reads a tenant-scoped input snapshot, parses and tokenizes it, and requests one vector per chunk outside SQL transactions. A 30-second heartbeat renews the 120-second lease using `renew_lease(factory, lease)`. Each vector is checked for finite normalized 1024-dimensional output. The final short transaction acquires Source then Job, rechecks revision/token/lease, inserts a complete generation and chunks, and calls the existing independent SQL activator. Rejected activation rolls back staging. A late/deleted/replaced job cannot overwrite a serving generation. `fail_job(..., code, retryable=...)` writes only fixed safe error codes under the same fence; transient processing failures back off 30/60 seconds, at most three claims. Expired final attempts are recovered through existing queue discovery. Failed updates leave the previous ready generation available.

The worker role remains nonowner, NOSUPERUSER, NOBYPASSRLS and NOINHERIT. It has no patient, appointment, auth, session or agent-version access. Provision its optional private password only through the existing `init_database(admin_url, app_password, worker_password=None)` interface or its `SCHEDULER_KNOWLEDGE_WORKER_PASSWORD` CLI input. Ordinary API initialization preserves an already configured worker credential. No migration or broad grant is added for ingestion.

## Document boundaries

All formats run through a disposable parser subprocess with a 20-second wall deadline, sampled 512MiB RSS cap, Linux address-space cap, CPU cap and bounded output. Input is at most 10MiB; extracted text is at most 1,000,000 characters. Invalid UTF-8, encrypted PDFs, pages without extractable text (including mixed scanned/text PDFs), more than 200 PDF pages, unsafe ZIP members, external DOCX relationships, more than 1000 archive entries or 50MiB expanded bytes fail the whole source. No OCR is performed. HTML is parsed as text; scripts/styles/templates are excluded and linked assets are never requested.

DOCX uses a small OOXML reader built on `zipfile` and `defusedxml`, rather than installing unused `python-docx`/lxml. Body paragraphs and table cells follow XML order. Header parts are read once in filename order, then the body, footnotes, endnotes and footer parts. This is text extraction, not visual page-layout reconstruction. Heading styles, tabs and line breaks are retained. Text boxes, drawings/images, embedded objects, altChunk content and unsupported parts containing text are rejected explicitly instead of silently producing an incomplete ready document. External hyperlink relationships are also rejected. Text-only PDF extraction does not infer visual headings; Markdown and DOCX preserve explicit headings.

Chunks use the exact pinned tokenizer JSON, verified by the existing profile's size and SHA256 before loading, with truncation and padding disabled. Content windows target 300–500 tokens with 50-token overlap, selecting English/Urdu sentence boundaries when they lie in that range; oversized sentences split at token offsets. Short sections and final tails can be smaller. Stored token counts include special tokens and never exceed 512. The 256-chunk limit rejects the entire source rather than dropping its tail.

Public URL fetching accepts HTTPS on port 443 only, rejects credentials, fragments and secret query parameters, validates every DNS answer and each redirect (at most three), and pins a validated public IP while retaining original TLS verification/SNI/Host. It rejects mixed public/private answers and IPv4-mapped addresses. Wire and gzip-decoded bytes are each bounded to 10MiB; other content encodings are rejected. An absolute 30-second caller deadline includes DNS, TLS, headers and body streaming; a timed-out background transport retains its single slot until it exits, preventing unbounded accumulation. No proxy/environment credentials are used. Tests use controlled resolvers/transports only.

## Blob ownership and retirement

Configure a fresh, independent, at-least-32-character `KNOWLEDGE_BLOB_SECRET` in the private Compose environment. It maps to API `SCHEDULER_KNOWLEDGE_BLOB_SECRET` and worker `KNOWLEDGE_WORKER_BLOB_SECRET`; it is never passed to the embedding service, browser or public API contracts. Do not reuse JWT, embedding, database, voice or provider credentials. Without it, API startup and protected JSON source edits work, but new binary uploads and blob cleanup fail closed. Existing committed blobs remain readable under their source ownership and checksum.

A new upload writes a private HMAC-SHA256 receipt binding the canonical server key, tenant, source, original upload revision, SHA256, size, device/inode and creation time. `BlobStore.receive` returns a `PendingBlob` holding an exclusive inode lock. The upload route releases that lock only after the outer SQL transaction commits or rolls back. A matching transaction advisory lock also protects server-side work whose outcome is unknown after client loss. The locks cover metadata completion, not network upload under row locks. Reindex retains and verifies the original upload revision's blob.

Cleanup requires the shared key, a valid receipt, matching inode/digest, no symlink/hardlink, no held upload/SQL fence, and an authoritative tenant-scoped reference check. It scans at most 100 directory entries per call and carries its cursor between sweeps. Current references and live job inputs survive. Deletion is immediate for retrieval but does not unlink its input immediately. On the first confirmed unreferenced observation, cleanup signs a retirement timestamp; deletion requires another full 24 hours. References reappearing reset retirement, and a newer source mutation conservatively restarts grace. Missing-source upload orphans also wait 24 hours after the first observation, not merely after creation. Receipt verification/SQL uncertainty leaves files untouched.

Unproven historical files, incomplete receipts and receipts signed with an older key are retained and still count toward physical quota. Rotating the key therefore stops automatic reclamation of old receipts; do not rotate without a separately reviewed reconciliation/migration procedure. Crash-before-receipt files also require that explicit reconciliation. No automatic adoption or guessed ownership is performed. This trades disk retention for avoiding unauthorized deletion. The 1GiB physical quota and 4GiB free-space reserve remain enforced.

## Deployment boundary

`compose.embedding.yaml` retains project `voice-agent-phase1`. The worker has no host port and receives only its narrow DB URL, embedding bearer, blob ownership key, private blob volume and readonly tokenizer file. It joins the existing project network for Postgres/public URL access and the private embedding network for RPC. It has one CPU, a 1GiB container ceiling, a 64MiB temporary filesystem and no extra capabilities. Its UID matches the API solely to access the existing mode-0700 private blob volume. The embedding service gets neither DB/raw-document mounts nor the blob key. Existing database image, services, addresses and volume names remain unchanged.

The `knowledge-worker` Docker target installs the locked `ingestion` group; API runtime does not install it. Package metadata/wheels were reverified on 2026-10-30: pypdf 6.21.4, BSD-3-Clause, universal Python wheel; defusedxml 0.7.1, PSF license, universal Python wheel. Tokenizers 0.23.3 and psutil 7.2.2 reuse the previously reviewed locked versions. Their distribution notices remain in the installed packages. CI keeps the optional test groups installed using `uv run --no-sync`, runs synthetic parser/worker boundaries and never downloads artifacts or performs real model inference.

The local Task 7 checkpoint provisions a private shared blob key and refreshes only the API after backup and additive migration. Worker/model execution remains disabled. See [checkpoint results](phase-5-results.md); real embedding/bilingual retrieval acceptance remains pending. No fixture vectors are written into development knowledge.
