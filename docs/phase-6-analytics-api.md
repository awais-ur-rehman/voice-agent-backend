# Phase 6 analytics read contracts and worker boundary

Task 4 is source implementation, not deployment qualification. Applied migrations 0001–0012 remain unchanged. Task 6 owns backup, provisioning, migrations and service rollout. No historical recovery backfill, model inference, notification delivery, or frontend implementation is included.

## Staff endpoints

Authenticated staff can GET `/dashboard/analytics/overview`, `/quality`, `/latency`, `/intents`, `/knowledge-gaps`, `/alerts` under the analytics prefix, plus `/dashboard/calls` and `/dashboard/calls/{session_id}`. Routes use live principal authorization and own-tenant forced RLS. Analytics filters require ISO dates `start` and `end`, inclusive, at most 31 dates; default `channel=voice`, optional `agent_id` and historic `timezone`. A foreign agent returns 404. Test-purpose calls never enter these projections. Date selection is the stored admission-local-date cohort, independent of later timezone changes or event time. The oldest selectable date is the UTC current date minus 365 days. Empty/zero-denominator metrics are null, with explicit counts.

Counters/quality use persisted daily rollups; response `freshness` includes worker `as_of`, stale flag, pending dirty buckets and pending authoritative expirations. More than 60 seconds without successful evaluation, unfinished raw expiry, or pending dirty work is stale. Missing worker state is explicit. Bounded/multi-batch alert evaluation or more than 100000 eligible alert latency samples withholds the all-tenant freshness marker conservatively. Historical counters remain available after raw data expires. Daily series and counters share a repeatable-read snapshot. Text and voice are separate cohorts, never summed implicitly.

Overview provides admitted/ended sessions, three session ratios, separate book/cancel/reschedule operations, ended-duration sum-derived average and sample count, and provider usage coverage. Booking conversion counts ended sessions with any canonical book operation, even if subsequently rescheduled/cancelled. Handoff rate counts ended sessions with the committed handoff event. Abandonment follows the safe terminal `abandoned` outcome, including unfinished/no-success explicit ends as classified by the accepted runtime lifecycle. Active sessions do not enter session outcome ratios. Quality exposes completed/attempted scheduling tasks, failed/all actual tool results, repeated/eligible completed scheduling prompts and task-assigned caller turns/attempted tasks. Eligible prompt categories are ask_date/need/patient/verification/slot/appointment and readback; interrupted, greeting, consent and information emissions are excluded from that denominator. No default initial book intent is fabricated.

Usage fields `invocations`, `usage_known`, `cost_known` are distinct. Input/output token totals cover the same invocations with both actually reported counts; partial usage stays in the ledger but is outside this paired aggregate. Totals are null when no paired usage exists. `estimated_usd` sums only costs with both reported counts and both configured USD-per-million rates; it is null when no cost is known. A configured zero rate is known. Covered estimates are not total bills and missing coverage is not free usage.

Latency computes PostgreSQL percentile_cont(0.5/0.95) from raw samples, never rollup percentiles. The entire selected admission date window must be within 90-day raw retention, using stored call and retained hourly-rollup offsets conservatively (including already-purged historical cohorts); outside coverage returns `unavailable_reason=raw_retention`. A single count gate bounds all returned stages together: 100000 allowed, 100001 returns `sample_limit` with null counts/percentiles rather than truncation. Each stage has samples, distinct sampled sessions, eligible sessions, null percentiles when absent, and a diagnostic flag. Canonical keys: command_total, tool, llm_completion, llm_first_token, stt_completion, tts_first_byte, end_of_speech_to_audio. Diagnostic keys: tts_buffered_generation, audio_queue, end_of_speech_to_audio_queue. Diagnostics do not fill absent TTFT/first-byte/published-audio metrics. Text cohorts have zero eligible sessions for voice-only stages.

Intents count distinct sessions per accepted scheduling task kind, completed information result or committed handoff. Each share uses all selected captured sessions as denominator. A session may have multiple intents; shares need not sum to 100%. This raw projection explicitly becomes unavailable outside retention.

Knowledge gaps group keyed fingerprint plus decision only. New server-owned runtime observations link to their session and follow admission-date/channel/timezone/agent filters. `below_threshold` contributes to `irrelevant`; no_sources/processing_pending/service_unavailable/stale contribute to `unavailable`, separately. `rejected` and `ready` remain explicit grouped decisions. Preview and legacy rows without a captured admission are counted separately in `unattributed_observations` using observed UTC date, without inventing channel attribution. No question, source, refs, patient, recovery or provider body is selected. Test child rows remain in their child tenant and are excluded from production counts.

Calls and alert histories use bounded seek pages, max100, with total, has_more and next_cursor. Opaque list cursors contain timestamp and UUID only; they confer no authority. Call details contain safe lifecycle fields, separate operation/task counters, a code-generated count summary and a bounded safe-event page ordered by server sequence ordinal. Facts are derived in that read snapshot rather than stored prose; capture's summary_revision remains its change marker, and summarized_at remains reserved/unused. The worker does not hold live call rows to render summaries. Raw call lists/details hide admissions older than90 days even if bounded cleanup is behind. Alert date filters use last_seen UTC date, explicitly labeled; backlog alerts have `channel=null`, because queue work has no voice/text channel.

## Manager text and settings

Owner/admin only: GET/PUT `/dashboard/analytics/settings`, GET `/dashboard/calls/{session_id}/transcript`, DELETE that transcript path. Settings PUT requires current revision, capture_enabled and retention_days1–30; conflict returns409. Capture remains off by default. Text responses are separate from staff detail; staff paths never SELECT transcript fields. Manager pages use a short separate repeatable-read transaction with Call → settings SHARE locks, current enable/retention/consent/tombstone checks, and server event ordinal seek pagination. Total/has_more prevent presenting the first100 messages as a full conversation. All analytics/call responses, including errors, are no-store. Redaction is imperfect and `residual_sensitive_content=true` remains explicit. Own deletion must clear displayed text in Task5; no client erasure promise is made.

Migration0013 refuses to invent order when existing captured turn history exists. The authorized local rollout has no prior analytics data; no sequence backfill from recovery or fabricated timestamps is performed. New ordinals are generated by PostgreSQL at safe-event insertion. Migration0014 adds nullable session attribution to knowledge audits with tenant/agent/session FK ownership; only the authenticated runtime log scope supplies it, while preview remains null. There is no historical attribution backfill or broader worker grant.

## Worker and operator metrics

`analytics.aggregation.run_once(factory, *, clock, limit=100) -> dict` clamps limit1–100 and returns bounded tenant/expiry/bucket/failure/skip counts. `analytics_worker.main` polls every10 seconds by default, disabled by default, and disabled `--once` does not create a database engine. Settings: ANALYTICS_WORKER_ENABLED, DATABASE_URL, POLL_SECONDS1–60, BATCH_SIZE1–100 with that prefix. Enabled configuration requires the analytics_worker username and qualifies NOSUPERUSER/NOBYPASSRLS/no inheritance or membership/no ownership/no clinical/auth/recovery/source grants/no transcript-text access. Existing credentials are not changed. Optional provisioning uses the existing SCHEDULER_ANALYTICS_WORKER_PASSWORD path; actual rollout remains Task6.

Discovery is worker-only and returns tenant IDs, including queue-only clinics, via ascending bounded cursor (max50). In-process cursors wrap fairly between polls and reset on restart. The tenant helper `analytics_agent_backlog(as_of, after_agent, batch_size)` returns only agent routing ID, queued count and age, max100, under current tenant; PUBLIC/app/knowledge-worker cannot execute it. There is no worker SELECT on knowledge jobs/sources/query events. Existing analytics_backlog remains compatible.

A per-tenant session advisory lock serializes worker instances, without participating in runtime locks. Expiry uses one Call transaction at a time and skip-locked selection; heavy recomputation never holds live Call row locks. A separate repeatable-read transaction replaces hourly/day counters from the same facts and acknowledges matching dirty revisions optimistically. Concurrent capture forces bounded serialization retry, retaining its revision/facts. Every query/worker transaction has a5s statement timeout and1s lock timeout. Hour keys use the snapshotted offset, including half/quarter-hour UTC minutes and distinct DST folds. A day is recomputed and sealed before its first90-day raw admission purge. Subsequent dirty rows cannot overwrite sealed counts with partial raw data. Purges are bounded and analytics-only: expired transcript rows,90-day call metadata/cascaded analytics children, resolved alert history90days, daily/hour counters365days. No source/recovery/clinical deletion occurs.

Alerts use rolling15-minute observation windows: canonical voice e2e p95>1500ms English or>2000ms Urdu with>=5 per-language samples; tool failures>10% with>=5 results;>=1 actual provider malformed/timeout/failure or ended-error session; queued knowledge age>900seconds regardless of queue size. The worst breached language owns the one open latency alert per agent/channel. Worker serialization plus a partial unique index prevents duplicate open state. Recovery resolves once; a later breach reopens a new history row. No notification delivery is configured.

`/private/analytics/metrics` is excluded from staff/public contract export and accepts only a distinct SCHEDULER_ANALYTICS_METRICS_SECRET Bearer secret; normal staff/owner JWTs are rejected. It returns a bounded process-local API projection-duration histogram, fixed endpoint and ok/error labels, and process-start reset time. It is not a global voice/cost registry; it makes no cross-tenant DB discovery query and contains no tenant/session/question labels. No OpenTelemetry exporter or external request is configured. No platform-wide HTTP owner report was invented; a separate platform cost CLI is not required for these tenant views and is deferred.

Task5 should use generated `packages/schemas/dashboard.v1.json`, preserve nulls, label estimated covered USD and diagnostic latency, show stale/coverage states, separate voice/text and legacy unknown attribution, invalidate all sensitive data on account changes, and clear its own transcript view immediately after deletion. Real voice-stage completion, production load, deployed worker execution and owner rollout remain unqualified until their explicit checkpoints.
