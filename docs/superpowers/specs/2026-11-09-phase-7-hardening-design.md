## 1. Bounded provider router

Keep Nemotron as the compatible public planner API (`plan`, `ground`, `close`) and preserve state-constrained schemas, disabled thinking, prompt boundaries and code-owned confirmations. Add an internal router/endpoint policy module, not another scheduler/tool stack. Primary defaults to nvidia/nemotron-3.5-bolt-e4b at the existing NVIDIA URL. Optional secondary model/base/key is configured independently; absent means unavailable, never invent another working model or reuse another account secret implicitly. Owner environment/key file is never loaded by tests or changed automatically.

Each HTTP attempt has a hard wall deadline3seconds; at most one secondary attempt per logical request, only on429,5xx or transport/timeout. Do not retry401/403, malformed/ineligible actions, policy errors or side effects. A logical planning request is bounded6seconds, grounding also honors its earlier absolute deadline. An unconfigured or locally throttled/open primary may use a configured secondary without HTTP to the primary. No hedge and no repeated chain. Capture every actual attempt with its own invocation UUID/model/provider/status/usage and explicit safe fallback provenance; refusals before HTTP do not fabricate invocations. Preserve independent billing records across domain rollback and late completion under healthy persistence. This remains bounded best-effort observation, not guaranteed billing durability during a database outage. Network/routing results must not wait on SQL telemetry: reserve actual-attempt metadata in memory at dispatch, report result/stage/usage to the caller within the routing deadline, then persist start/completion through the same bounded attempt worker before releasing its slot. No unbounded audit queue or extra per-observation thread. A stalled writer can occupy a bounded worker and reduce admission; unavailable records/cost remain unknown. Do not create a billable observation for work refused before HTTP. Provide a bounded drain(timeout) for orderly close and deterministic verification; do not hold application SQL locks or join indefinitely. Late persistence cannot mutate a result, create a tool action or reopen a closed measurement scope.

Use a configurable per-endpoint token bucket, conservative default10requests/minute with burst1, explicitly an operator budget rather than a measured NVIDIA quota; distinct models sharing one endpoint/key share the bucket. Retain the existing total process request budget across attempts. Circuit is rolling5failures in30seconds, open60seconds, one half-open probe; timeouts/429/5xx/transport errors count, malformed/policy/auth errors do not trigger failover. Concurrent and late outcomes cannot reset a newer open circuit. Clock is injectable for deterministic tests.

Bound outstanding provider network work (default4 primary+secondary attempts combined per process, configurable1–20), acquire without queueing, and release only when underlying HTTP work actually exits. Hard deadlines must not leave unbounded background threads; cancellation/close must preserve this bound. A slow primary that outlives its caller cannot execute a tool or replace a secondary result. No SQL lock while waiting for provider I/O. On exhaustion, existing upstream_timeout/callback behavior remains code-owned. Usage provenance uses additive0017: nullable fallback_from invocation UUID and route primary/secondary on analytics_usage, with bounded provider nim/openai_compatible labels; no endpoint URL or key is persisted. Extend the internal UsageObservation/MeasurementSink coherently and preserve legacy defaults. Primary/secondary base URLs must be HTTPS or literal loopback HTTP, with no userinfo/query/fragment; secrets remain server-only. Live secondary quality, actual NIM cap and target-network latency remain unqualified.

## 2. HTTP admission, security and privacy

Default-safe protection on current routes: route-specific body bounds before parsing (ordinary JSON64KiB; existing knowledge binary upload bounds remain authoritative; bounded header/query lengths where supported), reject invalid/negative/conflicting lengths and oversized streamed bodies; don't buffer arbitrary files or read an unbounded response merely to display an error. Enforce `Cache-Control: no-store` on auth, staff, runtime and private responses, including errors; security headers include nosniff/referrer policy. Do not introduce HSTS on HTTP localhost or claim TLS/encryption-at-rest deployment. Continue explicit CORS origins; CORS is not authorization.

Distributed login throttling uses PostgreSQL, not optional Valkey or process-local state: additive0018 migration with a purpose-scoped opaque-key bucket table/function, fixed search_path SECURITY DEFINER narrowly granted to scheduler_app, no raw IP/email/token stored and no broad table grant. Authenticate remains usable with foundation DB-only configuration. Atomic short separate admission transaction persists rejected attempts independently of login rollback. Limits are10login/minute/IP and30refresh/minute/IP; existing registration policy retained. Returned429 has bounded integer Retry-After and generic no-PII body. HMAC bucket identifiers derive a purpose-separated JWT secret; ignore user forwarded headers. Default runtime uvicorn explicitly disables proxy-header trust; document trusted ingress configuration for later deployment. DB unavailable fails closed503, never process-local fallback. Bucket expiry cleanup is bounded and safe under concurrent workers; growth/expiry semantics must be tested.

Staff new text/voice/draft admissions use30starts/10minutes per authenticated user and120/10minutes per transport IP, applied before expensive/provider/media work without charging exact idempotent voice/draft replay twice. Existing cleanup/end/heartbeat/consent/recovery/metrics must not be throttled by start admission. Preserve tenant/RLS/auth and idempotency semantics. No public endpoints are added. Existing single-worker CPU voice readiness/capacity is not raised to20.

Add drain admission flag (validated configuration, defaultfalse). In drain mode readiness503 and new text/voice/draft sessions503 with Retry-After; existing sessions, end/resume/heartbeat/worker cleanup, auth and staff recovery remain functional. No remote unauthenticated drain-toggle endpoint. Restarted configuration supports rolling-deploy admission; actual cross-node routing is not claimed.

Review/log redaction boundary with hostile bilingual inputs, validation fields/query paths/provider errors/signed URLs/authorization headers and exception paths. Logs expose fixed route/method/status/request-id/duration, never bodies, query values, credentials or PII. Existing transcript best-effort redaction/explicit consent caveats remain; do not claim arbitrary text is de-identified. Unexpected exceptions must return a generic envelope and safe diagnostic without upstream exception text. Security tests include tenant crossing, runtime vs staff credentials, spoofed IP/Origin, prompt/KB injection and callback unavailability; preserve existing guards rather than duplicate them.

## 3. Recovery tooling and isolated restore

Provide maintained operator backup/restore tooling and runbook using pinned installed PostgreSQL image/tools, standard-library orchestration and explicit opt-in. Automated tests use synthetic credentials and disposable targets only. Backup bundle contains custom-format DB dump, roles SQL, private knowledge blob snapshot and a versioned metadata/hash manifest. Outputs/directories are0600/0700; no DSN/password/SQL rows/PHI printed or committed. Capture a consistent database snapshot for digest+dump; verify role/blob manifests before/after and fail if they change during capture instead of claiming cross-resource atomicity. Do not alter owner roles/config/volumes.

Actual local recovery drill may read the current local development DB/roles/private blob volume and create a private bundle. Restore ONLY into a newly created dedicated disposable PostgreSQL container using the exact pinned pgvector image, network none, no published ports, bounded memory512MiB/CPU1, temporary PGDATA and temporary restore blob target. Bootstrap as a unique restore-only admin so saved CREATE ROLEpostgres can be restored without modifying its SQL. No existing container/database/volume is a restore target. Operator tool must validate this isolated target itself, not accept an arbitrary destructive DSN. Explicitly reject malformed/unexpected bundle paths, hashes, members and target identity. Never `--clean`/drop/reset owner DB, stamp/downgrade migrations or change source credentials. Use no persistent Docker volume and remove only this tool-owned disposable container after receipts.

Validate restored migration head, critical table row counts/digests, role flags and ownership, RLS behavior and blob byte hashes and authenticated ownership receipts with the retained existing HMAC blob key provided in process, without printing content/secrets. Blob bytes are plaintext; the secret authenticates ownership, not encryption. Verify each original signed receipt identity/size/hash and backup content before rebinding device/inode and re-signing ONLY the copied receipt in the newly created private restore directory, preserving its SQL key and retirement timestamps. Preserve original receipts. Test tampered signatures/identity/content, traversal, symlinks/hardlinks and mismatched versions before rebinding; never weaken live BlobStore.receipt or add an HTTP restore endpoint. Actual source files/receipts are untouched. Publish only counts/status/timings/hashes of synthetic-safe metadata; actual source/role/blob manifests remain private. This establishes measured local recovery, not encrypted off-site backup, an RPO/RTO SLA, or production failover. If resource admission prevents the real drill, retain tooling/tests and explicitly leave real recovery acceptance pending.
